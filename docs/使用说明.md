# 使用说明

## 配置与数据目录

界面右上角“配置”提供TMDB API密钥、Bangumi检索开关与可选Token、目标目录等设置。目标目录按电视剧、电影、动画和动画电影分别配置。凭据保存在运行数据目录，不写入源码或提交到Git。

| 环境变量 | 作用 |
| --- | --- |
| `BAR_DATA_DIR` | 配置、日志、任务、计划、登记和恢复记录的独立存放目录；默认是仓库下的`data/` |
| `BAR_UI_PORT` | WebUI端口，默认`5999` |
| `BAR_UI_STORAGE_SECRET` | NiceGUI存储密钥；需要使用时由本机环境提供，保持稳定并妥善保存 |
| `BAR_DRY_RUN` | 设为`1`阻断真实媒体执行；仍会保存配置、任务或计划等运行记录 |

首次检查可以在独立数据目录启动：

```powershell
$env:BAR_DATA_DIR = Join-Path $PWD 'data-preview'
$env:BAR_DRY_RUN = '1'
.\.venv\Scripts\python.exe -X utf8 -m src.start
```

使用独立样本检查目标布局，确认后在实际数据目录按需启动。`BAR_DRY_RUN`不是“完全不写磁盘”的承诺，也不替代审核和备份。

## 任务处理

添加来源后，任务进入后台队列。队列接纳只表示开始处理；是否成功应查看任务状态、计划内容和最终执行结果。

确认作品、季度和内容归属后，核对计划中的文件名及目标目录。需要修改纳入范围时使用来源内容操作；提示会随当前计划刷新。缺少资料、内容为空或有冲突时，按界面提示补充或修正。

批准只对应当前计划。更改来源、作品或计划内容后，应重新核对并批准新计划；不要手工修改保存文件来复用旧批准。

## 文件整理与恢复

当前计划执行采用硬链接，来源文件保留在原目录。来源和目标需位于同一支持硬链接的文件系统；容器中应通过同一个媒体挂载保持路径关系。

硬链接的两条路径共享文件内容。人工直接修改目标文件内容可能影响来源文件；字幕编辑与其他修改应走应用支持的流程或使用独立副本。

失败或中断时优先查看原任务和“菜单 → 恢复记录”。保留对应数据目录、计划、回执和媒体现状，不通过删除重建任务或修改登记文件强行继续。升级前备份完整数据目录，升级后先核对已有任务能否显示与继续操作。

## 下载完成通知

`/sendTask`可以接收下载完成通知。qBittorrent的示例命令如下，端口应与实际WebUI一致：

```text
curl --data-urlencode "path=%F" --data-urlencode "tag=%G" "http://127.0.0.1:5999/sendTask" -f
```

`path`必须是应用进程可访问的路径，容器部署时使用容器内路径。`tag`中的`anime`用于动画、`movie`用于电影、`no_process`用于跳过；也可显式传入`is_anime`。响应JSON中的`code`和`data`需要一并检查，HTTP请求成功不代表媒体整理完成。创建任务后仍需在WebUI核对和批准计划。

## 容器运行

构建方法见[开发与验证](开发与验证.md)。运行镜像时，将完整数据目录挂载到应用数据位置，将来源与目标共同挂到一个媒体根。以下为需要替换路径的示例：

```yaml
services:
  bar:
    image: bangumi-auto-renamer:0.3.0-rc.83
    ports:
      - "127.0.0.1:5999:5999"
    environment:
      BAR_DATA_DIR: /app-data
      BAR_DRY_RUN: "1"
    volumes:
      - ./data:/app-data
      - /path/to/media:/media
```

示例默认仅在宿主本机访问，并阻断媒体执行。实际启用执行前核对挂载、写权限与计划；根据自己的访问范围配置网络。这里没有发布预构建镜像下载地址，也不代表完成了新的容器或NAS验收。
