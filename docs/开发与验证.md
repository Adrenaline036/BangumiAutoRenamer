# 开发与验证

## 安装入口

本版本以Python 3.11验证。运行依赖使用[requirements.txt](../requirements.txt)，带固定版本与下载哈希；本地和Docker构建使用同一份清单。`pyproject.toml`记录项目元数据和直接依赖，不替代完整锁定清单。

```powershell
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

测试还需要pytest。应使用隔离环境和独立`BAR_DATA_DIR`，不要将正式数据目录交给测试。测试会创建、覆盖或清理临时文件；若环境要求所有删除进入回收站，必须使用对应的受保护测试运行器，不能直接运行带自动清理的全量套件。

## 测试范围

rc83的空内容提示与分页定向测试位于：

- `tests/test_empty_notice_refresh.py`
- `tests/test_issue_pagination_layout.py`

当前根工作区的上述组合为10个测试实例，已在Python 3.11开发环境通过定向验证；本地媒体检查在未指定样本时跳过。现有虚拟环境的`pip check`通过，但68项适用锁定依赖中49项与安装状态不同，因此这次定向结果不作为全新锁定环境安装验证。依赖清单按rc83交付原样保留，未自动升级或重建环境。当前仓库还保留各阶段的合同测试，部分旧夹具、旧接口和开发预览模块已不属于当前运行包，不能把它们描述成全量通过。特别是引用`development.preview`的旧预览测试需要其对应开发夹具；这些夹具不进入生产镜像。

`test_r1_real_media_production_red_contract.py`中的本地媒体检查仅在显式设置`BAR_R1_MEDIA_ROOT`后启用，未设置时跳过。该变量应指向自行准备的对应样本副本，不把个人目录写回测试代码。

静态语法、环境依赖自洽、锁定依赖一致性、定向测试、真实WebUI、容器和NAS验证属于不同层级。使用者反馈实际验收通过，不等于声明所有历史测试或所有部署环境都通过。

## 源码指纹与镜像构建

[指纹工具](../tools/source_fingerprint.py)只读取`src/`、`requirements.txt`、`start.py`和`LICENSE`，输出确定的SHA256；不读取配置、运行数据、测试或本地资料。Dockerfile按同一范围复制文件。

源码经审查并提交后，在干净工作区执行：

```powershell
$fingerprint = .\.venv\Scripts\python.exe tools/source_fingerprint.py
$buildId = git rev-parse HEAD
docker build --build-arg BAR_BUILD_ID=$buildId --build-arg BAR_SOURCE_FINGERPRINT=$fingerprint --build-arg BAR_APP_VERSION=0.3.0 -t bangumi-auto-renamer:0.3.0 .
```

构建前按[发布检查](发布检查.md)核对版本、清单和工作区状态。构建记录使用完整commit和源码指纹；不能用旧commit代表尚未提交的修改。镜像标签不能覆盖已有不同内容的版本。本次源码整理不等于已经执行上述镜像构建。
