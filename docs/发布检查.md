# 发布检查

## 公开范围

公开候选包含产品源码、可分发测试、构建与依赖文件、许可证、README、版本说明、使用与开发文档及只读源码指纹工具。发布前固定逐文件路径、长度和SHA256清单。

以下资料只留在本机：`local/`、运行数据与日志、配置文件、环境文件、凭据、浏览器记录、媒体、部署TAR、历史恢复清单、个人协作规则及本地编辑器设置。`.gitignore`不能自动取消已经被Git跟踪的文件；正式暂存前必须核对已有索引，并将本机资料从拟发布树中排除。

## 检查步骤

1. 核对`src/__version__.py`、`pyproject.toml`、文档和镜像标签使用同一版本。
2. 依据固定公开清单逐项检查新增、修改和退役文件；不要直接全量暂存未分类的文件。
3. 扫描工作树与拟推送历史中的密钥、Token、Cookie、私有地址、用户名及本地路径。测试占位符与真实凭据需要逐项区分，不以“扫描无输出”替代人工核对。
4. 核对应用文件、构建上下文和依赖与目标版本一致；记录实际执行的检查、定向测试及未验证范围。
5. 检查公开文档的本地链接，确认没有依赖`local/`中的私有资料。
6. 获得提交授权后，仅按清单暂存，再执行`git diff --cached --check`并核对暂存树。获得推送授权后才推送；发布Release和部署另行处理。

## 历史与反馈

当前工作树脱敏不代表历史提交已脱敏。如果拟推送历史仍包含私有资料，应先确定发布分支和历史处理方案，不自动重写历史或强制推送。

对外提交问题时，使用脱敏样本与最小错误片段，保留复现所需结构和状态，删除真实路径、凭据及完整媒体清单。截图也需检查地址栏、路径和账号信息。
